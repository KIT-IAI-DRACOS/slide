# SLiDE: Structured Linear Dynamics for Forecasting with Exogenous Inputs

Sebastian Pütz, Theodore Glavas, Benjamin Schäfer, Boris Oreshkin, and Mark Coates

SLiDE is a lightweight, Koopman-inspired architecture for multi-step time-series
forecasting with exogenous inputs. It reconstructs the current latent state with a
structured recurrent encoder and rolls that state forward with the same learned
linear dynamics, driven by future-known inputs.

## Repository layout

```text
.
├── config/
│   ├── dataset/          # Dataset definitions and train/validation/test splits
│   ├── model/            # SLiDE, ablation, and baseline configurations
│   └── tuned/            # Selected hyperparameters, one file per model and dataset
├── dataset/                 # Local CSV and Hugging Face/FEV data pipelines
├── models/
│   ├── slide/            # SLiDE implementation
│   └── ...               # Forecasting baselines
├── scripts/                 # Dataset preparation, including missing exogenous values

```

## Installation

The code was developed using Python 3.11 and uses
[`uv`](https://docs.astral.sh/uv/) for environment management.

```bash
git clone https://github.com/KIT-IAI-DRACOS/slide.git
cd slide
uv sync
```

Training metrics go through the Weights & Biases logger. A login is optional. With no API key, the logger runs offline and writes `wandb-summary.json` under the run directory at `wandb/offline-run-*/files/wandb-summary.json`. That file holds the logged test metrics, including MAE and MSE. To upload runs instead, log in and set the mode:

```bash
wandb login
WANDB_MODE=online uv run main.py
```

## Training

Run SLiDE on EPF-DE by default, select another dataset, or choose a model and dataset:

```bash
uv run main.py
uv run main.py dataset=epf_fr_712
uv run main.py model=tide dataset=favorita_1d_fev
```

Hydra loads `config/tuned/<model>/<dataset>.yaml` when it exists; otherwise it uses
the base settings. Command-line overrides still apply, including `model.seed`
(default `42`). Append `--cfg job --resolve` to inspect settings without training.

## Ablations

The four model ablations share [`models/slide/slide_ablations.py`](models/slide/slide_ablations.py). Each is a separate model config, and Hydra loads `config/tuned/<model>/<dataset>.yaml` for that pair:

| Model config | Change |
| --- | --- |
| `slide_nonlinear` | Nonlinear state update |
| `slide_mlp_encoder` | MLP initial state |
| `slide_state_dependent` | State-dependent exogenous map |
| `slide_transformer_encoder` | Transformer initial state |

```bash
uv run main.py model=slide_nonlinear dataset=epf_fr_712
```

Noisy future exogenous inputs are a dataset switch, off by default in [`config/config.yaml`](config/config.yaml). Set `dataset.horizon_ex_noise=true`. The noise scale is `dataset.horizon_ex_noise_scale` (default `0.5`). The helper is [`dataset/ex_noise.py`](dataset/ex_noise.py), and it applies only to local CSV datasets.

Missing exogenous values for local CSVs are prepared with [`scripts/add_missing_to_dataset.py`](scripts/add_missing_to_dataset.py). It masks the selected columns together and fills them with their full-file mean, then appends a `missing` indicator. Point `dataset.data_name` at the new file and increase `num_future_features` by one.

## Data

The experiments use three dataset families:

| Dataset | Source used by the code | Current setup |
| --- | --- | --- |
| [Electricity Price Forecasting (EPF)](https://zenodo.org/records/4624805) | Local CSV files | Download from Zenodo and place the CSV files in `data/epf/`. Keep the Zenodo headers unchanged. |
| Favorita grocery sales | Hugging Face/FEV | Downloaded automatically through the `datasets` package. |
| [Bouc–Wen system](https://data.4tu.nl/articles/dataset/Hysteretic_Benchmark_with_a_Dynamic_Nonlinearity/12967592) | Downloaded MAT files, converted locally | Download the source files from 4TU.ResearchData and prepare the CSVs as described below. |

Local datasets are expected in the repository's ignored `data/` directory:

```text
data/
├── epf/
│   ├── BE.csv
│   ├── DE.csv
│   ├── FR.csv
│   ├── NP.csv
│   └── PJM.csv
└── bouc-wen/
    ├── uval_sinesweep.mat
    ├── yval_sinesweep.mat
    ├── uval_multisine.mat
    ├── yval_multisine.mat
    ├── bouc_wen_combined.csv       # Generated by the preparation script
    └── bouc_wen_multisine.csv      # Generated by the preparation script
```

Download the original Bouc–Wen files from the
[4TU.ResearchData record](https://data.4tu.nl/articles/dataset/Hysteretic_Benchmark_with_a_Dynamic_Nonlinearity/12967592).
The download is a zip that contains `BoucWenFiles.zip`. Inside that second zip, extract the four validation .mat files and copy them into `data/bouc-wen/`. Then, generate both CSVs with:

```bash
uv run data/bouc-wen/bouc-wen_prep.py
```

The combined file contains the sinesweep samples followed by the multisine samples.
Both files use a zero-based integer `date` column.

## Outputs

Each run writes its resolved configuration, logs, best checkpoint, and W&B summary under:

```text
results/models/<model>/<date>/<run-name>/
└── wandb/offline-run-*/files/wandb-summary.json
```

`wandb-summary.json` is the test-metric file when the logger is offline. An online run uploads the same summary.
